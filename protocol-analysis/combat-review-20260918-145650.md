## Unmarked session-ending fault

At 15:01:32.158 the client drinks item23533 at inventory `1473:5`, slot9.
The timer starts, then frame checkpoint fails at 15:01:32.780 with:

`Unsupported modern item state: container=equipment slot=0 item=20137
(Torva full helm) amount=1 charges=0 attributes=true invention=false`.

This is a server-side strict save invariant failure followed by session closure,
not evidence of a Vulkan renderer crash. `Your local progress has been loaded.`
is sent on loading the persisted local player into a new session; it does not
mean the failed tick was saved successfully.

Isolated real-cache reproduction confirmed the producer: the Overload task's
self-hit enters `Entity.processHit`, which invokes legacy
`ChargesManagerNew.useChargeOnHit(false)`. In combat this replaces Torva with a
charged copy containing `ITEM_UUID` and `ITEM_CHARGES_DATA` (59,999 charges).
The native container format intentionally cannot save those fields. Native
combat otherwise avoids this legacy degradation path. The correction belongs
at the native/legacy hit boundary, not in permissive save validation. It also
avoids dereferencing an unhydrated legacy charge manager in isolated native players.

## Architectural findings

- Keep the live-proven `type << 17 | key << 4` shortcut representation and the
  separate preset config banks. The prior low-nibble repacking was the icon and
  context-menu root cause; adding more redraw scripts was not the remedy.
- Spell and ability shortcuts share the magic enum, but require different
  authoritative dispatch. Route recognised spell keys into the existing spell
  selection owner, not a second parallel spell state.
- Elveron876 retains a pending shortcut while GCD/cooldown blocks execution and
  gives manual requests precedence over Revolution. SHNORKSCAPE removes it
  before checking readiness. Preserve one pending request and execution-time
  validation rather than adding another queue.
- Elveron schedules channel damage from effect ticks, independently of visual
  sequence length. Current native follow-up spacing is derived from animation
  duration; modern sequences with zero legacy-frame duration collapse hits onto
  one tick. Gameplay timing must not be inferred from missing rendering metadata.
- Threshold admission currently uses the 15% consumption cost as its minimum.
  The mature EOC owner separates 50% admission from 15% consumption.
- Berserk currently boosts all damage, including a subsequent magic/ranged
  loadout. Its melee scope must be enforced at damage resolution.
- Native Prayer and Revolution settings were not exercised in this capture.
  Neither can be declared repaired from this session. Server Revolution was
  executing; retain it.
- The raw unhandled-frame log contains 1,194 sensor/control records, including
  key telemetry. Narrow diagnostic logging without changing packet processing;
  never publish raw input previews or private captures.

## Validation boundary

The real-cache Overload acceptance is offline and never loads a real character.
Unit tests, cache probes and Netty write success cannot prove visible icon,
animation, menu, layout or timing quality. Those require the next short live
Bug Test. Do not label unobserved native UI paths as fixed.

## Implemented checkpoints

- Native potion hits no longer invoke legacy equipment degradation. Both the
  unit test and real-cache five-hit Overload reproduction pass; strict save
  metadata validation remains unchanged.
- Manual requests survive GCD and may wait for their own cooldown only within
  a three-tick window. A waiting request suppresses auto-attacks, remains
  replaceable, and revalidates target/range/weapon/adrenaline. Thresholds require
  50% to start and consume 15%; Berserk only doubles melee damage. Positive
  tests now cover waiting successfully, not just cancellation after invalidation.
- Observed `1461:1` option2 now selects supported Air spells through the same
  owner as `;;spell` and bound spell shortcuts. Selection is persisted in the
  bounded settings section and publishes the existing varbit43 selection. Tests
  feed opcode122 through the real decoder, check outgoing bytes, reject a closed
  book and verify restore. Visible highlighting still requires a live check.
- Channel timing now belongs to the scheduled-hit owner. Relative EOC cadence
  is adapted from Elveron's EffectsManager COMBO_BUFFS: Fury 0/2/5, other
  two-tick channels at 0/2/4/... and Rapid Fire at one-tick intervals. Existing
  Alpha hit counts and coefficients are retained, not claimed as current retail
  balance. A channel protects its last scheduled hit from autos, Revolution,
  manual activation and incoming block animations; a queued request waits.
  Follow-ups cancel if channel range/style/hand requirements or player state
  become invalid. Projectile autos remain independent once launched.
- Prayer now translates current enum positions into the retained Prayer owner's
  logical identities. Current enums contain 28/45 entries while the owner has
  22/38; passing their positions straight through selected the wrong prayers or
  exceeded the arrays. All 60 supported activation bits are verified against
  current script7083 (SHA256
  `84edab8171cf068a09e424d3fdc83b535dba92ee887675733f8cc4f30699fb7a`).
  Delta-only activation updates avoid legacy parent-varp assumptions. Actual
  decoded grid clicks, requirements, exclusion, toggling, unsupported entries,
  damage/protection, points and unchanged-state silence have offline cache
  coverage. Native combat now consumes the existing offensive/defensive bonuses
  and style protection. This is not a port of curse reflection/leech/Soul Split.
  The unobserved Prayer input surface and visible highlights still need a live
  test; no speculative handler was assigned to wrapper1431:0.
- Unknown client traffic no longer records raw payload previews. It emits first
  occurrence metadata and bounded per-opcode totals at markers/session end.
  Decoded interface/drag/command telemetry is unchanged. This removes the
  sensor-frame flood without losing packet-count evidence or storing key data.

## Status presentation blocker

(add) or15426 (remove). Both use11293 ->11095/11294 to choose the parent:
`284:18` or `291:1`. Add goes through15425/15428 ->10626; remove goes through
15427/15428 ->10785. The child lookup follows params8100/8105/8106 and is
bounded to50 steps. No mount of these status panels exists in the present native
bootstrap. Timer4252 records a client-cycle expiry, including Overload23129.
Thus simply allowing4252/10624 would not establish visible status ownership.
The next step is deriving the native status panel layout/mount lifecycle, not
guessing a root slot or loosening the generic script guard.
