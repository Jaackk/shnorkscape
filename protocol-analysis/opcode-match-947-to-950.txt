How to read this
----------------
Produced by tools/match950.py, which walks each 947 packet parser (addresses from the 947
project's verified/verifiedNames.toml evidence comments), normalizes it to a shape-only token
stream with absolute addresses and rip displacements abstracted away, and scores it against every
950 handler parserTarget in protocol-analysis/950-native.json. Assignment is greedy over all
scores so no 950 opcode is claimed twice.

EXACT (>= 0.98) means the parser is shape-identical across revisions and the opcode mapping is
strong evidence. Anything below "strong" is a lead, not a result: the var family
(VARP / VARBIT / CLIENT_SETVARC / CLIENT_SETVARCBIT) parsers are near-identical to one another,
differing only in id width and value transform, so shape matching cannot separate them and they
need direct disassembly.

Independent cross-check against the descriptor lengths in 950-server-sizes.toml:

  RESET_CLIENT_VARCACHE  947:48  -> 950:23  size 0 both   AGREES
  UPDATE_RUNENERGY       947:116 -> 950:21  size 1 both   AGREES
  UPDATE_RUNWEIGHT       947:108 -> 950:7   size 2 both   AGREES
  UPDATE_REBOOT_TIMER    947:52  -> 950:31  size 2 both   AGREES

  CLIENT_SETVARCSTR_*    the two string variants CONFLICT with their 947 names.
    947 SMALL=67 is var-byte (-1) and writes string-then-id.
    947 LARGE=15 is var-short (-2) and writes id-then-string.
    In 950 the shape match pairs 947-LARGE's parser with opcode 30, which is var-BYTE (-1),
    and 947-SMALL's parser with opcode 81, which is var-SHORT (-2).
    So 950 pairs the opposite field order with each frame width. Do not port the names; port
    (opcode, layout) pairs and choose by encoded string length. Confirm by disassembling both
    950 parsers before sending either.

0x140107a42 and 0x140107a4d additionally fold BOTH u16 fields from 0xFFFF to -1, so the -1 slot
sentinel round-trips through the ushort128 encoding. All four addresses are 950.

score means the two revisions' code diverged, not that the assignment is doubtful. Every field in
