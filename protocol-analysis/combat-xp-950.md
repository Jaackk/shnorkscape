# Combat XP and floating XP drops, native 950

The implementation reuses the original 910 `PlayerCombat.delayHit` ratios and the existing `CombatDefinitions.giveXp` skill selections. Each actual player hit, capped to the victim's remaining HP, awards engine damage / 2.5 combat XP and engine damage / 7.5 Constitution XP. Misses and NPC retaliation award nothing, and death does not award a second copy. Displayed life points are ten times engine HP and must never be passed to this method.

`Skills.addXp` remains the XP engine. Its account-rate calculation and original custom curve (combat x7; noncombat x3.5) now use a shared helper, and both client paths share the existing XP commit, current/base levels, 200-million cap, tracker arrays, level-up healing and stat refresh. The native branch avoids optional legacy seasonal/pet/invention/quest/social callbacks whose managers or client content have not been ported. Those optional boosts and rewards are not silently claimed as supported. The original default melee selections share XP among Attack, Strength and Defence; the original mutable selection array is respected, but its settings UI and persistence are not part of this change.

Schema 3 already captures/restores the actual `Skills` double experience and current level arrays through `Native950PlayerBinder`; no parallel XP store or schema change was added. Native account flags currently default to the existing fallback XP rate (IRONMAN_XP = 1 in this source); combat's x7 custom curve is unchanged from 910.

No invented XP notification, legacy script signature, or chat substitute is used.

134 exact component/script/enum/struct/varbit records are pinned in `Native950XpDrops` and `xp-popups-950-evidence.json`. `tools/verify_950_xp_popups.py` verifies those pins and selected normalized CS2 instructions. Automated frames establish correct publication; visible rendering remains a client test, and a login burst must not be mistaken for newly earned XP.
